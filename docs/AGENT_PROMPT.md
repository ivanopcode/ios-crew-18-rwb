# Задание агенту: собрать репозиторий доклада на Slidev с темой «RWB tech»

Ты работаешь в пустой директории. Рядом лежит комплект `slidev-rwb-kit/` (этот файл — часть комплекта). Цель — рабочий репозиторий Slidev, в котором доклад «Локальные модели для разработки под iOS на Apple Silicon» открывается, собирается и экспортируется в PDF в стиле темы. Работай по шагам, после каждого проверяй результат командой, не переходи дальше при ошибке.

## Контекст стиля

Стиль описан в `slidev-rwb-kit/README.md` — прочитай целиком до начала. Кратко: тёмный типографический developer-session, одна композиция на слайд без построений, брендовые акценты RWB с закреплённой семантикой (сирень — модель, оранжевый — цена, лайм — проверка), логотип только на титуле и финале, векторные пиксельные мотивы только на титуле, открывашках и финале, без карточек, бенто, 3D, теней и градиентов. Язык слайдов — технический русский без лозунгов и без конструкций «не X, а Y».

## Шаг 1 · Инициализация

1. Проверь `node --version` (нужен ≥ 20) и `pnpm --version`; если pnpm нет — `corepack enable && corepack prepare pnpm@latest --activate`.
2. Создай `package.json` проекта:
   ```json
   { "name": "podlodka-ios-local-llm", "private": true, "type": "module",
     "scripts": { "dev": "slidev slides.md --open", "build": "slidev build slides.md", "export": "slidev export slides.md --output dist/podlodka-ios-local-llm.pdf", "export:pptx": "slidev export slides.md --format pptx --output dist/podlodka-ios-local-llm.pptx" },
     "devDependencies": { "@slidev/cli": "latest", "@slidev/types": "latest", "playwright-chromium": "latest", "vue": "latest" } }
   ```
3. `pnpm install`. Комплект проверен на Slidev 52.19.1 (`slidev build` проходит для витрины и для порта). Затем узнай установленную версию Slidev (`pnpm slidev --version`) и открой актуальную документацию по темам и раскладкам (sli.dev/guide/write-theme, sli.dev/custom/directory-structure, sli.dev/custom/config-highlighter) — если конвенции изменились относительно комплекта, приведи файлы темы к текущим.

## Шаг 2 · Тема

1. Скопируй `slidev-rwb-kit/theme/` в корень репозитория как `theme/` (локальная тема подключается строкой `theme: ./theme` в headmatter `slides.md`).
2. Проверь, что структура соответствует текущим конвенциям Slidev: `layouts/*.vue`, `components/*.vue`, `styles/index.ts`, `setup/shiki.ts`, `uno.config.ts`, `global-bottom.vue`, `package.json` с полем `slidev.defaults`. Если Slidev ругается на схему `package.json` темы — исправь по документации, содержимое стилей не меняй.
3. Запусти витрину: `pnpm slidev theme/example.md`. Открой в браузере, пройди все 12 слайдов. Убедись: шрифты Inter и JetBrains Mono загрузились; логотип виден на титуле и финале; код в `code-side` раскрашен (флаги сиреневые, значения оранжевые); строки 7–8 подсвечены фоном; таблица с сиреневой шапкой; `<Boxes>`, `<Stack>`, `<BigNum>`, `<PixelMotif>` рендерятся.
4. Если какая-то раскладка или компонент падает — чини в `theme/`, не в слайдах. Типовые причины: изменившееся API `useSlideContext` в `global-bottom.vue` (можно заменить на `$slidev.nav.currentPage`), формат `themes` в `setup/shiki.ts`, импорт PNG в `RwbLogo.vue` (альтернатива — положить логотип в `public/` и использовать `/rwb-logo-white.png`).

## Шаг 3 · Слайды

1. Скопируй `slidev-rwb-kit/slides.md` в корень. Это черновой порт 55 слайдов из pptx: раскладки выставлены по простым правилам, заметки спикера (абзацы авторского текста) — в HTML-комментариях, их не сокращать и не переписывать.
2. Запусти `pnpm dev`. Пройди слайды по порядку и приведи раскладки к образцу из `theme/example.md`, опираясь на `slidev-rwb-kit/content/14_ios_crew_v6_outline.md` (какой пункт текста на каком слайде) и `slidev-rwb-kit/content/v6_slides_dump.md` (текст каждого слайда в исходном порядке):
   - сравнения двух сущностей (dense/MoE, prefill/decode, интерактив/автономный, режимы, кто ждёт) → `two-cols` с `::right::`;
   - последовательности шагов (читают → вызывают → проверяют → повторяют; связка; знания; harness) → `<Boxes>`;
   - слои (слои за терминалом, путь от среды до кеша, компетенция стека) → `<Stack>` с цветом первого слоя `lilac`, для «компетенции» — `lilac`, `lime`, `orange`;
   - числа (2 ч 47 мин; $4.57 / $9.13; 288 / 864 тыс.) → `<BigNum>`;
   - граф фичи Notes, цикл проверки, роутер, ветки на одном сервере, память как полоса — inline SVG по правилам из README §4 (узлы `--rwb-node` с цветной обводкой, рёбра `--rwb-sec`, подписи 13 px mono);
   - таблицы оставить Markdown-таблицами;
   - список «План» — две колонки по пять пунктов с номерами моноширинным сиреневым.
   Открывашки частей (`layout: section`) добавь перед частями 1–10 только если автор попросит; по умолчанию их нет.
3. Правила текста при правках: заголовки — утверждения или вопросы; никаких «не X, а Y»; факты и числа не менять — они из авторского текста; плейсхолдеры `<Ph>⟨…⟩</Ph>` не заполнять выдуманными значениями.

## Шаг 4 · Проверки

1. `pnpm build` — без ошибок и предупреждений о неизвестных компонентах.
2. `pnpm export` — PDF собрался; открой первые, средние и последние страницы: переносы заголовков не залезают на контент, таблицы не обрезаны, код не мельче 16 px, ничего меньше 13 px.
3. Пройди чеклист из README §7 и выпиши в `NOTES.md` слайды, где содержание не помещается: их нужно разбивать на два слайда, а не уменьшать кегль.
4. Сделай коммит `chore: slidev deck on rwb-tech theme` с `.gitignore` (node_modules, dist, .slidev).

## Чего не делать

- Не добавлять анимации, `v-click`, переходы между слайдами и автопрокрутку.
- Не добавлять логотип на рабочие слайды и не увеличивать его.
- Не менять цвета темы, не вводить новые акценты, не использовать фиолетовые заливки на всю страницу.
- Не переписывать заметки спикера и не «улучшать» формулировки слайдов сверх правил из шага 3.
- Не подключать сторонние темы или иконочные наборы.

Отчёт по завершении: версия Slidev, список изменённых файлов темы (если менялись под новую версию), список слайдов, где раскладка изменена с `default` на что-то другое, и список слайдов из `NOTES.md`.
